MarioSouls world collision update — local build 0.6
11 October 2026

Installed change
Mario's movement is now submitted to Dark Souls' own character physics. The game resolves collisions with its live world, and the resolved position is sent back to Mario. The old normal-play loop that teleported Mario while disabling native map collision has been replaced.

Mario still uses libsm64 movement, jumps and animations. Strength, Dexterity and Mario upgrades keep their separate combat role. Weapons do not select Mario's attack power. Existing controller controls and visible Mario interactions are retained.

Live native contacts supply temporary floor/wall surfaces to Mario. They are rebuilt each frame in a fixed, bounded buffer. This lets Mario stand and jump on a solid object without keeping a stale surface after walking off or after destruction. The rendered model follows the resolved native body.

Object attacks now use the native object-damage entry point with Mario's own attack records and paid attack window. Native object health, destruction rules, effects and collision removal remain in charge. Object and enemy hits share the per-attack target limit; repeated frames do not create repeated hits.

Interaction controls
Y on the controller or Q on the keyboard requests an interaction. The game's prompt still shows its native A button. Give the handoff about one second. Use normal menu controls while interacting; Mario returns automatically. Q now has its own delayed confirmation when no controller is connected.

Native restrictions still apply
A locked door needs the appropriate key or event. The main Asylum entrance is currently disabled by its native encounter state; native human mode cannot open it either. Some pillars and scripted walls can only be broken by a boss, boulder or event. Mario's attacks do not bypass those rules.

Limits of this validation
This is still an experimental local integration. The checks above cover the Asylum fixtures, not every map, elevator, moving platform or scripted wall. The Oscar wall was already disabled in this test character's event state, so a fresh intact-to-destroyed Oscar-wall sequence was not fabricated. Static map conversion limits remain as listed in the controls file. Mario's adapted door/climbing poses are not exact hand/foot matches to every native animation.

Safety and reproducibility
Only the existing level4 character named test was used. The level65 character was not loaded. Existing saves were copied for backup, never restored or edited. Native enemies were reset by resting at a bonfire. Failed setup attempts and older development measurements remain in their dated folders; do not treat them as final passes.

The standalone contact-surface checks passed support, extent, replacement, removal and 10,000 refreshes. Combat policy checks and all 10 harness measurement tests passed. Installed source matched the build, and Restore original game.ps1 -CheckOnly passed without changing files.
