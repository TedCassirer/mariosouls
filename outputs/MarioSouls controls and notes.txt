MarioSouls — experimental local build 0.7

Installed for Dark Souls: Prepare to Die Edition (Steam, 32-bit).

START PLAYING
Load your test character, then press F6 to switch into Mario. F6 switches back to the Dark Souls character. F7 resynchronizes Mario with your current position.

KEYBOARD AND MOUSE
WASD: move relative to the camera.
Mouse: Dark Souls camera.
Space: jump. Timed repeated jumps use Mario's double/triple-jump rules.
Left mouse button: punch, kick, or dive, depending on movement and airborne state.
Ctrl: crouch. Press Ctrl while airborne to ground pound.
Q: interact. E: use the selected item directly, including Estus.
Run, hold Ctrl, then press Space: long jump.
Stand still, hold Ctrl, then press Space: backflip.
Jump into a wall and press Space again promptly: wall kick.

CONTROLLER (XBOX BUTTON POSITIONS)
Hold both stick clicks (L3 + R3) together for about one second: switch Mario on/off. Release before toggling again. F6 still works.
Left stick: analog walking/running relative to the camera.
Right stick: normal Dark Souls camera.
A (bottom face button): jump.
B (right face button): punch, kick, or dive.
LT: crouch; press in the air to ground pound.
Run, hold LT, then press A: long jump. Stand still, hold LT, then press A: backflip.
Y (top face button): interact with the nearby object. The normal game prompt still shows A.
X (left face button): use the selected item directly, including Estus. No Y press first.
Start: open the Dark Souls menu while Mario stays visible.
The controller is detected automatically and reconnects after unplugging. Keyboard and mouse remain available. Slight stick drift is ignored. Mario's movement, A/B/Y and LT are withheld from the native game while Mario is active so jumping does not also interact with a ladder.

INTERACTIONS WHILE STAYING MARIO — 0.7
Y / Q requests the nearby action. X / E uses the selected item. These buttons no longer enter a human movement mode. If an action cannot start, you retain Mario movement.
Mario remains the same character through an accepted action, with blended drinking, sitting/standing, climbing or door poses. Movement resumes when the actual action finishes. Dark Souls controls item charges, healing, keys, interaction requirements and world changes.
On ladders: left stick up/down, or W/S. Climbing animation follows actual travel and pauses when you stop. Mario resumes after dismounting.
At bonfires and in menus: native menu controls, A to confirm and B to back out; Enter on keyboard. Leave the bonfire, let Mario stand, then jump normally.
Start / End opens the normal menu. Closing it returns to Mario. The interface continues to draw over Mario.
F6 or the stick-click shortcut remains the manual Mario on/off switch; Y is exclusively an interaction request. Avoid manually switching while attached to a ladder.

Verified on the test character: direct Estus, native healing and one charge, bonfire rest/leave/jump, ladder down/pause/up/dismount/jump, a locked-door message, menu close/resume, walking after a rejected request, and bloodstain recovery. Native incoming damage and death still work. See "MarioSouls interaction update.txt" and the accompanying demonstration.
Fresh NPC dialogue could not be replayed because Oscar is already dead on this save. NPC scripts use the same native action route, but that flow needs a live conversation test. Other items and special scripted interactions have not all been checked. Mario's adapted poses do not exactly match every native handle or ladder rung.

Mario uses the actual libsm64 movement and animations extracted locally from your ROM. His attacks call Dark Souls' damage routine. Dark Souls remains responsible for enemy health, deaths, souls, and your character's health. The test hollow took damage from Mario's attacks and awarded 20 souls when defeated.

FAST TEST LAUNCH
Double-click “Launch Mario test.cmd” beside this file. Leave the keyboard and mouse alone while it navigates the game menus. It recognizes the existing character named “test” before selecting that save. It stops if it cannot recognize a screen. It requires the current 1280×720 game setting and the installed Codex Python/Universal Modder tools. Normal Steam launch also works.

Startup logos are skipped by a version-checked hook. The original title movie was restored after testing; all original movies are present. Normal game timing is unchanged. Set SkipIntro = 0 in mariosouls.ini before launching to restore the logos.

The final installed launcher reached the loaded test character in 23.1 seconds in a clean launch test. It automatically acknowledges the autosave notice. Timing varies with loading and window focus. Keep Dark Souls in the foreground until the character appears.

UI DRAWING FIX (0.6.1)
Mario now draws before native interface sprites and text. The bonfire prompt and system menu correctly cover Mario, and menu text stays readable. Verified on the level-4 test character, including resting, leaving and jumping afterward.
The same draw boundary covers native text, but Oscar dialogue was already exhausted on this save, so a fresh NPC subtitle replay was not verified. The existing world depth test is retained.

CURRENT LIMITS
Combat/progression update: see "MarioSouls combat and progression.txt" for the independent Mario power formula, eight attack costs, weight penalty, health/fall rules, testing settings and measured results. Stat scaling is enabled with upgrade level +0. Actual glove inventory/titanite upgrades are still proposed.
This is an experimental integration, not a fully tested playthrough mod. The Asylum was tested in the actual game; other areas have not had the same gameplay testing.
Terrain caches are installed for 15 areas. Mario activation is disabled in Darkroot and Great Hollow/Ash Lake because their collision conversion is incomplete.
Movement now passes through Dark Souls' native collision system. Enemies, closed doors, and intact props block Mario; breaking a prop removes its native collision. Live contact surfaces let Mario stand on solid props and react to walls. The static map cache still supplies navigation geometry. See 'MarioSouls world collision update.txt' for the new tests and remaining limits. Moving elevators and scripted destruction outside the tested Asylum fixtures still need gameplay validation. Camera behavior remains the game's camera and can be cramped indoors.
Mario mode, including interaction display, turns off on death, a character/map change, or a detected large native teleport. Press F6 again only after loading finishes and your character is on solid ground.
The in-game clip verifies jumping, punches and ground-pound animation. Long-jump physics passed the separate runtime test; wall kicks, triple jumps, every attack variant, and a complete playthrough have not all been verified in this integration.

RESTORE
Quit through System > Quit Game, then close Dark Souls. Run “Restore original game.cmd”. It checks the installed file hashes, removes this mod's input loader and restores the original title movie. Saves are not changed. Backups and the dormant MarioSouls folder are retained.
