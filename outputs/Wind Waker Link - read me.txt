WIND WAKER LINK — FIRST PLAYABLE BUILD
Souls Character Framework 0.4, 11 October 2026

Installed in your existing Dark Souls Prepare to Die Edition folder. Launch through
Steam, select Mario QA, then press F6 to activate Link. The game is currently closed;
Mario QA is saved beside the courtyard bonfire at full health. Test controls are off.

Keyboard and mouse
- Move: WASD
- Jump: Space
- Sword: left mouse. Tap again during a swing to queue the next combo hit.
- Roll: Ctrl while moving
- Spin attack: Ctrl + left mouse from a grounded idle/run
- Interact: Q
- Use the selected native item: E
- Native menus: normal Dark Souls controls, including Enter to confirm
- Toggle character mode: F6

Controller mapping
- Left stick: move; A: jump; B: sword; LT while moving: roll
- LT + B from a grounded idle/run: spin attack
- Y: interact; X: use item
- Hold both stick buttons: toggle character mode
No controller was connected during this verification pass. The shared mapping
passes its executable tests; a fresh physical-controller test is still outstanding.

What is working
Link's original model, textures, equipment and 25 animation clips are extracted
privately from your USA disc. Walking, running, jumping, rolling, three sword
attacks, spin attacks and bonfire rest/leave were tested in the game. Closed doors
remain solid. Sword damage, enemy deaths, soul rewards, incoming melee damage,
native stamina and bonfire healing were verified on Mario QA. Text/UI draws above
Link. Neither jumping nor rolling grants additional invulnerability.

First-build limits
This uses an authored controller, not the complete Wind Waker engine. The shield
is visual: blocking is not implemented. Target lock, parries, bow, boomerang, sailing,
automatic ledge jumps, guest voices/sounds and facial animation are not implemented.
Ladder, door, dialogue and drinking presentation clips are connected to the shared
interaction interface, but have only offline pose checks in this Link pass. Mario QA
does not yet have Estus. Boss balance, other areas, hazards and death/respawn need
further testing. Combat values are provisional; exhausted swings animate without
dealing damage. Equipped Dark Souls weapons do not determine Link's sword power.
Link currently uses native fall-damage rules. Mario's reduced-fall profile is unchanged.

Checkpoints and switching back
- To return to Mario: close Dark Souls, then run
  "Restore Mario size and fall checkpoint.cmd" in this folder.
- To return to this Link build: close Dark Souls, then run
  "Restore Wind Waker Link checkpoint.cmd" in this folder.
- Both restore helpers preserve the files they replace and do not change saves.
- Link source tag: checkpoint-2026-10-11-framework-v0.4-link
- Mario source tag: checkpoint-2026-10-11-framework-v0.3-body

Keep the private runtime archive under work/checkpoints/ and Link's private pack at
work/link-ww/v1/link.scmesh with this project. Git contains source and verification
metadata, not the RVZ, extracted game assets, saves, binaries or captures. Never use
git clean -fdx here. Do not overwrite the v1 pack when preparing future versions.

The framework now supplies reusable skeletal asset loading, skinning, cutout
materials and static collision queries. Wind Waker-specific archive handling,
animation names and movement rules remain in its own character adapter.
