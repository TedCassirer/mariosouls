# PTDE native integration inventory

Use this inventory when maintaining PTDE hooks or planning a future Remastered host. Each row records a boundary's purpose, inputs, outputs and verification method. File names are relative to this host directory; numeric native values are evidence for the supported PTDE executable only.

PTDE is implemented; Remastered is not. x64 compilation does not translate these addresses, calling conventions, renderer states or asset formats. Focused stock/DSfix game checks are historical evidence, not confirmation that every integration below has current full-game coverage. See [compatibility](../../../docs/COMPATIBILITY.md) and [manual verification](../../../docs/TESTING.md).

## Preserve these native assumptions

The stamina setter has integer arguments while its native callers can retain live floating-point state. Preserve flags/general registers and x87/SSE/MXCSR around the C++ callback. Do not replace it with a general-register-only wrapper or widen x86 naked/register hooks mechanically for x64.

Native positions/support use metres; SDK positions/geometry use local centimetres with explicit conversion. Actor/movement/camera identities are transient and scoped. Native target generations must still resolve to the same actor before damage or HP confirmation.

On-disk indices/offsets, native pointers and SDK scalars have distinct meanings. A 64-bit process does not turn every 32-bit file field into a pointer. Asset/executable hashes establish source identity for that edition, not cross-edition compatibility.

## Maintaining and using this list

For each native boundary change, update its row and the relevant host source guide. Record the changed signatures/layouts, ownership/failure behavior and how it was inspected or checked. Update [Features and tweaks](../../../docs/FEATURES_AND_TWEAKS.md), [CHANGELOG.md](../../../CHANGELOG.md) and the [SDK contract](../../docs/CONTRACT.md) when resulting behavior/contracts change.

For a new host, rediscover the responsibilities in this table against an owned installation, implement edition-specific validation, compile the intended targets and establish manual evidence before changing support claims. Use the [host-porting guide](../../docs/HOST_PORTING.md) for renderer, timing, capability and installation obligations.

Use disposable characters; never test on the owner's level-65 character. Agent-driven input needs a current handoff. No test lab, save-editing automation or simulated-host runner is implied by a verification-method column.
